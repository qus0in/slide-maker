# 확산 모델이 이미지를 만드는 방식

> **확산 모델 (Diffusion Model)**
>
> 무작위 노이즈에서 출발해 점진적으로 이미지를 복원하는 생성 모델

- **역방향 과정 (생성)**: 순수한 가우시안 노이즈에서 시작해 노이즈를 조금씩 차감
- **순방향 과정 (학습)**: 원본 이미지에 노이즈를 단계적으로 섞어 완전한 노이즈로 변환
- **학습 목표**: 신경망이 각 단계별로 "얼마만큼의 노이즈가 추가되었는가"를 예측하도록 학습
- **결과물**: 무작위 노이즈 패턴에서 시작하지만 매번 정밀한 이미지 구조를 완성

---
layout: default
---

# 노이즈를 걷어내는 디노이징 과정

> **디노이징 (Denoising)**
>
> 무작위 노이즈에서 신경망이 예측한 노이즈 성분을 스텝별로 걷어내어 선명한 형상을 복원하는 과정

- **스텝(Step) 단위 복원**: 한 번에 복원하지 않고 $t=T$부터 $t=0$까지 수십 번 분할 수행
- **노이즈 예측 신경망**: U-Net / DiT 모델이 현재 입력 상태의 노이즈 패턴을 계산
- **점진적 형상 출현**: 초기 스텝에서는 거친 윤곽·구도가, 후반 스텝에서는 세부 질감이 완성
- **조건부 제어**: 프롬프트 임베딩 조건에 부합하는 방향으로 노이즈 걷어내기 방향을 유도

# 압축된 공간에서 연산하는 잠재 확산

> **잠재 확산 모델 (Latent Diffusion Model)**
>
> 픽셀 공간이 아닌 압축된 잠재 공간에서 디노이징을 수행하는 확산 모델

- **픽셀 공간의 한계**: $512 \times 512$ 픽셀 연산은 GPU 메모리와 시간 소모가 큼
- **잠재 공간 전환**: 이미지의 핵심 특징만 저차원 잠재 공간(Latent Space)에 응축
- **효율적 디노이징**: $1/64$로 줄어든 공간에서 반복 연산을 수행해 속도 향상
- **최종 복원**: 노이즈 제거 완료 후 디코더를 거쳐 고해상도 이미지로 변환

# 이미지를 압축하는 VAE 인코더

> **변분 오토인코더 (VAE, Variational Autoencoder)**
>
> 고차원 픽셀 데이터를 의미 있는 저차원 잠재 표현으로 압축하고 복원하는 모델

- **특징 추출**: 단순 픽셀 나열 대신 구도·색상·질감 등 의미적 핵심 특징을 추출
- **차원 압축**: VAE 인코더가 $512 \times 512 \times 3$ 픽셀을 $64 \times 64 \times 4$ 잠재 표현으로 압축
- **연산 부담 절감**: 사람이 인지하기 어려운 픽셀 디테일을 압축해 디노이징 연산 대폭 절약
- **역할 분담**: VAE 인코더는 잠재 공간 압축을, VAE 디코더는 최종 픽셀 복원을 담당

# 텍스트가 생성을 조건화하는 방식

- **인코딩**: 텍스트 인코더가 프롬프트를 임베딩으로 변환
- **개입**: 디노이징 각 스텝에서 cross-attention으로 반영
- **텍스트 임베딩과 비교**: 그때는 임베딩을 검색에 사용
- **이번 차시**: 같은 임베딩을 생성의 조건으로 사용

# 생성 결과를 좌우하는 핵심 파라미터

| 파라미터 | 의미 | 영향 |
| :--- | :--- | :--- |
| `steps` | 디노이징 반복 횟수 | 많을수록 품질↑ 지연↑ |
| `guidance` | 프롬프트 반영 강도 | 높으면 충실, 과하면 부자연 |
| `seed` | 노이즈 초기값 | 고정 시 결과 재현 가능 |
| `width`/`height` | 출력 해상도 | 클수록 연산량 급증 |

# 증류로 스텝을 줄인 few-step 모델

- **증류(Distillation)**: 교사 모델의 결과를 학생 모델이 압축 학습
- **효과**: 20~50 스텝을 1~4 스텝으로 줄여도 유사한 품질
- **대표 모델**: FLUX.1 schnell(독일어로 "빠른")
- **적합 환경**: 지연이 짧아 서버리스·엣지 환경에 적합

# 같은 프롬프트도 매번 다른 이미지

- **원인**: seed를 고정하지 않으면 노이즈 초기값이 매번 다름
- **결과**: 동일 프롬프트라도 실행마다 다른 이미지 생성
- **주의**: 이미지나 그 해시로 캐시 키를 만들 수 없음
- **대안**: 프롬프트와 seed 조합을 중복 판정 기준으로 사용

# 아직 남은 한계

- **텍스트 렌더링**: 이미지 안 글자를 정확히 그리기 어려움
- **취약 사례**: 로고나 정확한 문구가 필요한 요구사항
- **비용 구조**: 해상도가 커질수록 처리할 타일 수가 증가
- **결과**: 스텝당 연산량도 늘어 비용이 가파르게 상승

# Cloudflare Workers AI

> **워커스 AI (Workers AI)**
>
> 전 세계 엣지 네트워크의 GPU 위에서 오픈소스 모델을 서버리스로 실행해주는 추론 플랫폼

- **서버리스 추론**: GPU 프로비저닝 없이 HTTP 요청 한 번
- **모델 카탈로그**: 텍스트 생성·임베딩·이미지 생성·음성 제공

# 왜 Workers AI인가

- **REST 직접 호출**: 이미지 생성 모델을 `RestClient`로 연동 가능
- **동일 플랫폼**: 텍스트 임베딩에서 다룬 `bge-m3`와 같은 플랫폼
- **요금 정책**: 변동이 잦으므로 공식 문서에서 최신 내용 확인

- **OpenAI 호환 계층**: `/chat/completions`, `/embeddings`만 지원

# 본 실습의 선택

- **커스텀 `ImageModel`**: 공통 입·출력 타입은 그대로 유지
- **공급자 전용 옵션**: seed·steps 때문에 `CloudflareImageOptions` 사용
- **교체 영향 범위**: 공급자 교체 시 서비스의 옵션 생성부도 수정
- **규약 유지**: 컨트롤러·화면의 반환 규약은 변경 없음

# 설정 작성 시 주의점

- **자격 증명**: 환경변수로 참조하고 파일에 값을 직접 넣지 않음
- **예약 문자 `@`**: `@cf/`로 시작하는 모델 ID는 따옴표 필수
- **Duration 바인딩**: `timeout`은 `60s`·`2m` 표기를 그대로 사용

# 호출부에서 걸려 넘어지는 지점

- **모델 ID 인코딩**: `@`·`/` 때문에 URI 변수로 넘기면 404 발생
- **200이어도 실패**: 응답의 `success`와 이미지 존재 여부를 반드시 확인
- **접두사 위치**: `b64Json`에는 순수 Base64만, Data URI는 화면에서 조립
- **타임아웃 필수**: 무제한 대기는 요청 스레드를 고갈시킴

# 화면에서 조심할 것

- **버튼 비활성화**: 중복 제출만 막는 편의 기능, 사용량 제한이 아님
- **비동기 분리**: 실무에서는 작업을 분리하고 상태 폴링을 검토
- **Base64 보관**: 여러 요청에 들고 다니지 않음(약 33% 증가)
- **예외 처리**: 전역 예외 처리(`@ControllerAdvice`)로 사용자 메시지 변환
