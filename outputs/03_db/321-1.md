# JDBC 개요

> **JDBC (Java Database Connectivity)**
>
> 자바 애플리케이션과 관계형 데이터베이스(RDBMS) 간의 통신과 SQL 질의 수행을 표준화하기 위해 오라클(Oracle) 사가 정의한 자바 표준 데이터베이스 연동 API

- **추상화 인터페이스**:
  - DBMS 제품군에 직접 종속되지 않는 범용 인터페이스(Connection, Statement 등)로 개발
- **드라이버를 통한 런타임 결합**:
  - 런타임에 데이터베이스에 적합한 드라이버를 변경 결합하여 애플리케이션 유지보수성 극대화

# JDBC 드라이버

> **JDBC 드라이버 (JDBC Driver)**
>
> 자바 표준 API를 각 SQL 데이터베이스 소프트웨어별 독자적인 통신 규약에 맞춤식으로 구현한 개별 벤더사의 커넥터 라이브러리

- **데이터베이스별 전용 라이브러리**:
  - MySQL, Oracle, PostgreSQL, SQLite 등 사용하는 DBMS에 특화된 드라이버 탑재 필수
- **커넥터 확보**:
  - 예시로 MySQL 데이터베이스를 사용할 경우 `mysql-connector-j` 라이브러리를 의존성에 확보해야 연동이 가능

# Maven을 통한 JDBC 의존성 설정

- **빌드 도구 의존성 관리**:
  - 자바 프로젝트 빌드 관리 도구인 Maven의 `pom.xml` 설정 파일에 커넥터 라이브러리 정보 등록
- **자동 빌드 경로 배치**:
  - 라이브러리를 수동으로 다운로드받는 대신, Maven이 자동으로 원격 저장소에서 확보하여 빌드 경로에 배치
- **MySQL 드라이버 의존성**:
  - `groupId`는 `com.mysql`, `artifactId`는 `mysql-connector-j`로 선언하여 의존성 블록 구성

# 환경 변수를 통한 연결 정보 전달

- **하드코딩 배제 권장**:
  - 데이터베이스 접속 주소, 비밀번호 등 민감 정보를 자바 소스코드에 직접 하드코딩하지 않음
- **정보 노출 보안 사고 예방**:
  - 소스코드 유출 시 데이터베이스 자격 증명(Credentials) 도난을 차단하기 위한 필수 보안 조치
- **운영체제(OS) 환경 변수 주입**:
  - 시스템이나 개발 도구(IntelliJ 등)의 실행 환경 변수(Environment Variables)에 값을 등록해 연동
- **핵심 연결 정보**:
  - `DB_URL` (또는 `JDBC_URL`), `DB_USER`, `DB_PASSWORD` 등 설정

# JDBC 5단계 연동 프로세스 개요

> **JDBC 데이터베이스 연동 5단계**
>
> 자바 애플리케이션 환경에서 원격 데이터베이스와 통신하고 데이터를 가공한 뒤 소켓 연결을 소멸시키기 위해 준수해야 하는 규범적 실행 순서

- **1단계: 드라이버 로딩 (Driver Loading)**: DBMS 고유 드라이버 클래스를 JVM 메모리에 로드
- **2단계: 커넥션 생성 (Connection)**: 네트워크 통신 채널인 Connection 객체 획득
- **3단계: 구문 객체 생성 (Statement)**: SQL 질의를 수송할 Statement/PreparedStatement 생성
- **4단계: 쿼리 실행 및 결과 처리**: executeQuery() 등으로 질의를 던지고 결과 응답 처리
- **5단계: 자원 반납 (Close)**: 리소스 고갈 방지를 위해 획득한 JDBC 객체들을 역순으로 해제

# Statement와 SQL Injection

> **Statement**
>
> 정적 SQL 구문을 실행하기 위한 단순 구문 객체

- **매번 발생하는 파싱과 분석**:
  - 실행 시마다 SQL 문장 구조를 분석하고 최적화 계획을 새로 생성하여 전송
- **SQL Injection (SQL 삽입 공격)**:
  - 문자열 결합 과정에서 사용자가 입력값에 악의적인 키워드나 제어 문자(예: `' OR '1'='1`)를 삽입하여 원래의 쿼리 논리 구조를 왜곡·우회하는 취약점
- **보안 위험 노출**:
  - 검증되지 않은 데이터를 그대로 문자열로 결합하므로 데이터베이스 전체가 침해될 가능성이 농후함

# PreparedStatement와 보안 우위

> **PreparedStatement**
>
> 실행하고자 하는 SQL 쿼리 뼈대를 매개변수 위치홀더(`?`)와 함께 사전에 미리 컴파일(Pre-compile)해 두는 구문 제어 객체

- **SQL Injection 차단**:
  - 바인딩된 입력 데이터를 명령문이 아닌 단순 값 리터럴로 강제 변환하므로 쿼리 구조 변조를 원천 봉쇄
- **성능 최적화 (Pre-compilation)**:
  - 최초 1회만 구문 분석 및 실행 계획 수립을 수행하고 캐싱하여, 파라미터 값만 바꿔가며 고속으로 재사용 가능

# Statement 문자열 결합 방식

```java
// 사용자의 입력값을 그대로 문자열로 접합하여 쿼리를 생성
String input = "admin' OR '1'='1";
String sql = "SELECT * FROM users WHERE id = '" + input + "'";

// 매번 SQL을 파싱하며, SQL Injection 공격에 취약함
Statement stmt = conn.createStatement();
ResultSet rs = stmt.executeQuery(sql);
```

# PreparedStatement 안전 바인딩 방식

```java
// 위치홀더(?)를 사용하여 쿼리 프레임워크를 미리 컴파일
String sql = "SELECT * FROM users WHERE id = ?";
PreparedStatement pstmt = conn.prepareStatement(sql);

// 데이터를 무해한 값 리터럴로 바인딩하여 SQL Injection 차단
pstmt.setString(1, input);
ResultSet rs = pstmt.executeQuery();
```

# ResultSet과 결과 커서

> **ResultSet (결과 집합)**
>
> SELECT 쿼리의 호출 결과로 반환된 테이블 데이터를 논리적으로 내포하고 있는 가상의 데이터베이스 응답 객체

- **결과 커서 (Cursor)**:
  - 결과 레코드를 순차적으로 가리키는 내부 포인터로, 초기 커서는 첫 번째 행 이전(Before First)을 지시
- **행 전진 기능**:
  - `next()` 메서드 호출 시 다음 행으로 한 단계 전진하며, 읽을 데이터가 존재하면 `true`를 반환
- **컬럼 값 추출**:
  - 커서가 가리키는 현재 행의 특정 타입 데이터를 `getString()`, `getInt()` 등의 메서드로 안전하게 획득

# ResultSet 데이터 추출 코드

```java
String sql = "SELECT name, age FROM users";
try (PreparedStatement pstmt = conn.prepareStatement(sql);
     ResultSet rs = pstmt.executeQuery()) {
    
    // next()로 레코드가 존재하는 동안 반복하여 데이터 추출
    while (rs.next()) {
        String name = rs.getString("name");
        int age = rs.getInt("age");
    }
}
```

# JDBC 보안 핵심 2대 대책

- **1. 환경 변수를 활용한 접속 정보 은닉**:
  - 소스코드 내에 접속 계정명과 비밀번호를 하드코딩하여 관리하면 유출 즉시 보안 사고 직면
  - 접속 정보는 OS 환경 변수나 외부 격리 설정 파일로 완전히 차단하여 기밀성을 보호해야 함
- **2. PreparedStatement 활용을 통한 공격 원천 차단**:
  - Statement 방식은 악의적 사용자 입력에 의해 쿼리 구조가 왜곡되어 SQL Injection에 노출됨
  - PreparedStatement는 쿼리 뼈대를 미리 컴파일하고 매개변수 바인딩하여 오직 안전한 리터럴 데이터로만 연동

# CRUD 개념 정의 (1/2)

> **CRUD**
>
> 대부분의 컴퓨터 소프트웨어가 가지는 가장 기본적인 데이터 처리 기능인 생성, 조회, 수정, 삭제를 묶어 일컫는 용어

- **Create (생성)**:
  - 시스템에 새로운 레코드를 생성하여 저장 매체에 보관. SQL의 `INSERT`에 대응
- **Read (조회)**:
  - 기존 보관소 데이터를 검색하여 읽어오는 기능. SQL의 `SELECT`에 대응 (전체 및 조건부 단건)

# CRUD 개념 정의 (2/2)

- **Update (수정)**:
  - 기존 데이터를 조건에 맞게 찾아 새로운 내용으로 갱신. SQL의 `UPDATE`에 대응
- **Delete (삭제)**:
  - 불필요해진 레코드를 완전히 제거하거나 비활성화 처리. SQL의 `DELETE`에 대응

# JDBC 데이터 삽입 (Create)

- **SQL INSERT 작성**:
  - 새로운 데이터를 추가하기 위한 `INSERT INTO` 쿼리 템플릿 작성 및 파라미터 `?` 매핑
- **executeUpdate() 호출**:
  - 데이터를 입력받아 바인딩한 후 `executeUpdate()` 메서드를 호출하여 원격 테이블에 전송
- **영향받은 행 수 반환**:
  - 쿼리가 성공적으로 반영되면 삽입된 행(Row)의 개수가 정수(int) 값으로 반환됨

# JDBC 데이터 삽입 코드

```java
String sql = "INSERT INTO users (name, email) VALUES (?, ?)";
try (PreparedStatement pstmt = conn.prepareStatement(sql)) {
    // 파라미터 인덱스에 맞춰 데이터 바인딩
    pstmt.setString(1, "홍길동");
    pstmt.setString(2, "hong@example.com");
    
    // 영향받은 행(Row) 개수 리턴
    int rows = pstmt.executeUpdate();
}
```

# JDBC 데이터 조회 (Read)

- **SQL SELECT 실행**:
  - 특정 조건이나 전체 레코드를 읽어오기 위한 `SELECT` 쿼리 템플릿과 PreparedStatement 사용
- **executeQuery() 호출**:
  - `executeQuery()`를 수행하여 쿼리 결과를 나타내는 `ResultSet` 객체를 획득
- **자바 객체 구조화**:
  - 루프를 돌며 ResultSet 데이터를 꺼내 엔터티(Entity)나 DTO(Data Transfer Object) 등 자바 객체로 변환하여 관리

# JDBC 데이터 수정 및 삭제 (Update & Delete)

- **Update (데이터 수정)**:
  - 식별자(PK) 조건과 새 데이터를 바인딩하여 `UPDATE` 쿼리를 조립한 후 `executeUpdate()` 호출
- **Delete (데이터 삭제)**:
  - 삭제 대상을 식별하기 위한 유일값(PK)을 매핑하여 `DELETE` 쿼리를 구성
- **물리적 삭제 집행**:
  - `executeUpdate()`를 실행해 데이터베이스 상에서 레코드를 완전 배제하는 물리적 삭제(Hard Delete) 구현

# 학습 요약 (Summary)

- **JDBC와 드라이버**:
  - 자바와 관계형 데이터베이스를 잇는 표준 API로, 벤더사별 전용 JDBC 드라이버 탑재 및 Maven 의존성 관리가 필요
- **JDBC 5단계 연동**:
  - 드라이버 로딩 $\rightarrow$ 커넥션 생성 $\rightarrow$ 구문 생성 $\rightarrow$ 실행 및 처리 $\rightarrow$ 자원 반납의 규범적 사이클 준수
- **보안과 성능 (PreparedStatement)**:
  - 접속 자격증명 하드코딩 배제를 위해 환경 변수를 쓰고, SQL Injection 차단과 캐싱 성능을 위해 PreparedStatement를 강제
- **JDBC CRUD 구현**:
  - SELECT 조회는 `executeQuery()`와 `ResultSet` 커서를 쓰고, INSERT/UPDATE/DELETE 조작은 `executeUpdate()`로 실행
