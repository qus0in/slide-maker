# SQL 방언과 ANSI 표준

> **SQL 방언 (SQL Dialect)**
>
> 표준 SQL 규격을 존중하되, 성능 최적화와 편의를 위해 각 데이터베이스 관리 시스템(DBMS) 제조사가 독자적으로 구현한 문법 및 함수

- **ANSI SQL**:
  - 모든 RDBMS 제품군에서 공통으로 지원하는 국제 표준 SQL 규격
  - 데이터베이스 제품군 간의 높은 호환성과 이식성을 제공하는 역할을 수행함
- **제조사별 차별성**:
  - 각 DBMS는 성능 한계를 극복하거나 개발 편의를 돕는 전용 내장 함수와 특화 구문을 제공함

# 주요 데이터 타입 (Data Types)

> **데이터 타입 (Data Types)**
>
> 테이블 구조를 설계할 때 각 열(Column)에 들어갈 값의 형식과 크기를 규정하는 표준 자료형

- **수치형 타입**: 정수 데이터를 다루는 `INT`/`INTEGER`, 소수점 이하 데이터를 정밀하게 기록하는 `DECIMAL` 등이 대표적임
- **문자형 타입**: 고정된 크기의 텍스트를 저장하는 `CHAR`, 가변 길이의 텍스트 데이터를 공간 효율적으로 저장하는 `VARCHAR` 등이 대표적임
- **날짜/시간형 타입**: 날짜만 다루는 `DATE`, 날짜와 시각을 모두 기록하는 `DATETIME`, 그리고 시간대(Timezone) 변경에 유연하게 대응하는 `TIMESTAMP` 등이 있음

# 데이터 정의어 (DDL)

> **데이터 정의어 (Data Definition Language)**
>
> 데이터베이스 내 객체(테이블, 뷰, 인덱스 등)의 논리적/물리적 구조를 정의, 변경, 삭제하는 데이터 정의어

- **CREATE**: 새로운 데이터베이스나 테이블 등의 구조적 객체를 생성함
- **ALTER**: 기존 객체의 구조(컬럼 추가, 변경, 삭제 등)를 수정함
- **DROP**: 데이터베이스나 테이블 객체 자체를 물리적으로 완전히 삭제함
- **TRUNCATE**: 테이블의 껍데기(구조)는 남겨둔 채 내부 데이터 전체를 고속으로 초기화함

# 데이터 조작어 (DML)

> **데이터 조작어 (Data Manipulation Language)**
>
> 테이블 내의 레코드(데이터)를 삽입, 수정, 삭제하는 데이터 조작어

- **INSERT**: 테이블에 새로운 행(Row) 데이터를 추가 삽입함
- **UPDATE**: 테이블에 기재된 기존 레코드의 값을 수정함
- **DELETE**: 특정 조건에 일치하는 기존 레코드를 삭제함
- **DML과 트랜잭션**: DDL과 달리 DML 작업은 트랜잭션의 제어를 받으며 Commit/Rollback의 대상이 됨

# 데이터 질의어 (DQL)

> **데이터 질의어 (Data Query Language)**
>
> 테이블에 저장된 데이터를 사용자가 원하는 형태와 조건에 맞춰 검색하고 가져오는 데이터 질의어

- **원래 DML의 일부**:
  - 학술적인 데이터베이스 표준 분류 체계상 `SELECT` 문은 데이터 조작어(DML)의 일부로 간주됨
- **실무상의 독자 분류 (DQL)**:
  - 데이터 변경을 유발하는 연산(CUD)과 달리, 단순 읽기(Retrieve) 작업의 특수성을 고려하여 실무 및 개념상 DQL로 명확히 분리하여 인지함
- **DQL의 안전성**:
  - 데이터 자체를 변형하지 않아 트랜잭션 롤백 대상이 아니며, 무결성 훼손 리스크로부터 안전하여 쿼리 튜닝 및 분산 처리에 특화됨

# 데이터 연산의 기본, CRUD

> **CRUD (Create, Read, Update, Delete)**
>
> 대부분의 컴퓨터 소프트웨어가 가지는 가장 기본적인 데이터 처리 기능인 생성, 조회, 수정, 삭제를 일컫는 말

- **소프트웨어의 핵심 기능**:
  - 사용자 정보 등록, 게시물 열람, 정보 수정, 계정 삭제 등 거의 모든 애플리케이션의 핵심 로직을 구성함
- **백엔드 설계의 근간**:
  - REST API(POST, GET, PUT, DELETE) 설계 등 현대 웹 시스템 아키텍처 및 비즈니스 연산 모델의 기본 틀로 작용함

# DQL 문법 구조

> **DQL 문법 구조 (DQL Structure)**
>
> RDBMS에서 조건에 맞는 데이터를 정밀하게 검색하기 위해 약속된 표준 SELECT 질의 템플릿

- **선언적 템플릿**:
  - 데이터가 저장된 물리적 경로를 지정하지 않고, 최종 결과물의 형태와 조건만을 선언하여 데이터를 추출함
- **절(Clause)의 조합**:
  - 필터링, 그룹화, 집계, 정렬, 페이징 처리를 위해 미리 정의된 7가지 절을 정해진 순서대로 작성하여 결합함

# 표준 SELECT 질의 템플릿 구조

```sql
SELECT [DISTINCT] column_list
FROM table_or_view
[WHERE filter]
[GROUP BY column_list]
[HAVING group_filter]
[ORDER BY column [ASC|DESC]]
[LIMIT offset, row_count];
```

# DQL의 주요 절과 기능 (1/2)

- **SELECT / DISTINCT**:
  - 조회할 데이터의 컬럼 목록을 지정하며, `DISTINCT` 키워드를 함께 사용하여 중복 행을 제거함
- **FROM**:
  - 데이터를 검색할 대상 테이블명이나 가상의 뷰(View) 명칭을 기술함
- **WHERE**:
  - 원본 데이터 테이블로부터 특정 조건에 매칭되는 행만 1차적으로 걸러내기 위해 사용함

# DQL의 주요 절과 기능 (2/2)

- **GROUP BY**:
  - 특정 컬럼의 데이터를 기준으로 결과를 그룹화하여 합계, 평균 등의 집계 정보를 연산함
- **HAVING**:
  - 그룹화 연산이 완료된 최종 세그먼트 데이터에 대한 필터링 조건을 부여함
- **ORDER BY**:
  - 검색 결과를 특정 컬럼 기준의 오름차순(`ASC`) 또는 내림차순(`DESC`) 정렬로 제어함
- **LIMIT**:
  - 최종 출력 결과 중 특정 인덱스(`offset`)부터 지정한 개수(`row_count`)만큼만 슬라이싱하여 리턴받음

# DQL 주요 연산자와 함수 (1/2)

- **비교 및 논리 연산자**:
  - 동등 및 크기 비교(`=`, `!=`, `>`, `<`, `>=`, `<=`)를 수행함
  - 다중 조건을 묶는 `AND`, `OR`, `NOT` 및 범위 지정을 돕는 `BETWEEN` 연산자를 제공함
  - 복수 값 비교를 위한 `IN`, 부분 텍스트 와일드카드 매칭을 위한 `LIKE`를 제공함
- **NULL 처리 함수**:
  - 빈 값(NULL) 탐지용 `IS NULL` 및 `IS NOT NULL` 연산자를 사용함
  - NULL 값을 특정 대체값으로 치환해주는 `COALESCE` 또는 `IFNULL` 함수를 활용함

# DQL 주요 연산자와 함수 (2/2)

- **문자열 처리 함수**:

- **조건 제어 식 (CASE)**:
  - 쿼리 실행 도중 조건 분기 처리를 위한 `CASE WHEN ... THEN ... ELSE ... END` 구조를 활용함

# 쿼리 실행 순서의 논리적 흐름

- **쿼리 작성 순서와의 불일치**:
  - SQL 작성 시에는 `SELECT`가 가장 먼저 기재되나, 실제 DB 엔진 내부의 해석은 완전히 다름
- **최적화된 단계적 순서**:
  - 데이터의 로딩, 필터링, 그룹화, 최종 투영 및 정렬 단계를 거쳐 가장 효율적인 방식으로 동작함
- **실행 단계 순서**:
  - `FROM` ➔ `WHERE` ➔ `GROUP BY` ➔ `HAVING` ➔ `SELECT` ➔ `ORDER BY` ➔ `LIMIT` 순으로 엄격하게 해석됨

# 실행 단계별 세부 해석 (1/2)

- **FROM (1단계)**:
  - 질의 대상인 원본 테이블이나 뷰를 물리 디스크 또는 버퍼 캐시에서 찾아 로딩함
- **WHERE (2단계)**:
  - 로딩된 데이터 로우를 순회하며 개별 행 단위로 필터 조건을 비교 대조해 참인 로우만 필터링함
- **GROUP BY (3단계)**:
  - 필터링된 개별 행 데이터를 지정된 기준 컬럼의 값에 따라 논리적 그룹으로 나눔
- **HAVING (4단계)**:
  - 생성된 논리 그룹 중 집계 조건(HAVING)에 참인 그룹만 2차로 걸러냄

# 실행 단계별 세부 해석 (2/2)

- **SELECT (5단계)**:
  - 최종 추출 및 집계 완료된 결과 셋에서 표시할 컬럼 목록만 투영(Projection)하고 Alias를 부여함
  - *중요*: SELECT 절은 HAVING보다 늦게 처리되므로, SELECT 절에서 부여한 Alias를 WHERE/GROUP BY/HAVING 절에서 참조할 수 없음
- **ORDER BY (6단계)**:
  - 추출 및 가공이 모두 끝난 결과 데이터들을 특정 컬럼 기준에 맞추어 오름/내림차순 정렬함
- **LIMIT (7단계)**:
  - 최종 정렬된 레코드셋 중 지정된 시작점(offset)부터 한계치만큼만 끊어서 반환함

# 핵심 정리 : SQL 방언과 기초 및 데이터 질의어

- **SQL 방언**: ANSI SQL 표준 규격을 바탕으로 하되, 각 RDBMS(예: MySQL) 제조사마다 독자적으로 성능 향상과 편의를 위해 구현한 고유 문법 및 함수
- **데이터 타입 & SQL 분류**: 컬럼을 구성하는 다양한 수치형·문자형·날짜시간형 데이터 타입이 존재하며, 데이터베이스 구조를 다루는 DDL, 데이터를 조작하는 DML, 데이터를 조회하는 DQL로 분류됨
- **DQL 구조 & 실행 순서**: SELECT 질의는 정해진 문법 템플릿을 따르며, 실제 데이터베이스 엔진에서는 쿼리 작성 순서가 아닌 `FROM ➔ WHERE ➔ GROUP BY ➔ HAVING ➔ SELECT ➔ ORDER BY ➔ LIMIT` 순으로 해석되어 실행됨
